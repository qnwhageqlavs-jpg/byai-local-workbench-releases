## 0.6.2
日历维护移至系统设置的“园区与业务配置”，移除生成排期页重复的执行状态按钮。保存日历不会自动重新排布或同步实际任务。

检查通过且尚未开始执行的任务，可以在任务配置调整线路和并发，自动局部校验通过后仍待执行；旧确认失效，原历史和快照保留，同批其他任务可分别执行。已开始执行或写入结果未知的任务继续锁定；单次同线路累计超过1000并发仍须确认。

默认内置读取器的相同文件核验可跨重启复用。首次升级可能重建一次缓存，外部Python每次重新准备文件；凭据变化与话术有效期校验保持。刷新文件池仅凭唯一一致的内容证据恢复原绑定，不自动替换为名称相似的其他包。

## 0.6.1
统一任务状态与客服选择记忆；执行记录提供筛选、分页和右侧详情抽屉。诊断导出失败保留工作台，部分日志不可读时保留原文件并说明缺失；任务配置的“更新开工凭证”直接定位 CSMS 配置。

未执行排期按日期正序，已执行倒序；仪表盘和执行记录均可选择每页10/20/50/100条。保留原数据和历史，schema仍为7。

## 0.6.0
默认使用独立窗口，右下角托盘可打开和退出；关闭窗口可选择收起或退出并记住选择。设置按用途分区。

执行记录改为紧凑列表，依据失败阶段提供安全的重新执行或接续；已有远端任务不重复创建。检查失败保留具体中文原因，批量检查按任务隔离，共享故障只暂停受影响的后续任务。诊断包补充安全原因码。

系统设置内置推广模块参考，可按名称或编号搜索，园区名称自行填写，现有映射不自动改动。更新器明确区分 GitHub 限流、访问受限与真正缺少发布附件。

schema 仍为 7，数据和历史保留。旧客户端首次升级若卡住，可备份并退出后用官方 Setup 覆盖安装；缺少 WebView2 的压缩更新暂用浏览器模式。外部写入结果不明仍须人工核对。

## 0.5.2
修复部分客群、批量查询 Excel 表格范围错误导致的清洗识别失败。重复批量导入同名任务时，按园区预览话术及重要性变化，确认后更新，保留任务身份与数据包绑定；取消则整次不应用。重要性按重点、启用、待定、停用递减，升级浅绿集中在前，降级浅红集中在后。第三步行内“开始检查”只检查当前任务。

数据库 schema 仍为 7，话术、排期、执行历史和环境配置保留。正式版、测试版数据独立。已卡住的旧更新器仍可用本版官方 Setup 覆盖安装，保留原 profile 和数据目录。

## 0.5.1
第三步可组合筛选、检查和执行当天任务，第四步查看执行进度与恢复。单条或批量开始只处理选中的检查通过任务。同一线路本次并发超过 1000 时需要额外确认。

任务配置支持批量自动保存和搜索线路。设置页重排，CSMS Token 保存时去除首尾空白。启动回执异常时会核验原任务，未创建的任务可重新检查。程序重启后会恢复遗留的下载状态。

旧版本下载或安装已经卡住时，退出工作台后运行 0.5.1 官方 Setup 覆盖原程序目录，保留环境配置和数据目录。
